# 扬州井底药箱：T-37401H V1.000 限定修复

## 已确认的问题

正常游玩在扬州井底宝库开箱时，画面提示获得药品，库存却没有增加。
同一合法开箱前存档，在旧稳定 Linux 版本与 618fa7e 对应版本均复现。
后者实际 SDL 键盘路径也复现，因此并非新快捷键造成。

从用户自备、已校验的台湾版镜像独立解析后，确认 scene 93 的 event 1661
调用脚本 36785；脚本 36788 的 opcode 31 原参数为 object=0、quantity=0。
游戏将非正 quantity 正常化为 1，但原给物函数拒绝 object 0。
道具表、使用脚本（恢复 HP 1000，上限仍由原游戏处理）、描述及另一合法
给物脚本共同指向道具 103「紫菁玉蓉膏」。提示文本有字形差异，判定并非只凭名字。

## 修复范围与安全门

增加 PROG 06028700 的生成钩子，在原给物调用之前，仅当 scene、章节基数、
事件局部索引、脚本指针与无符号脚本编号、原命令、原调用指令及参数全部匹配，
将调用参数 r4 从 0 改为 103。数量仍为 1，物品入包、堆叠、宝箱空箱状态及存档
均走原游戏逻辑。没有改写存档、共享脚本、RNG、计时或通用 object 0 行为。
共享该脚本的另外三个事件尚未实玩确认，本修复不命中它们。

CMake 同时检查私有 build/disc-extract 中三文件的完整 SHA256：

- PROG.BIN: 808acfdb56a885a3949a8f3910705e077edb974d9985327e887acfba20afad6d
- CM.NOR: 9eff4c279978567837df146719a9632876f0ef6d0440b26009d8415cc01774f3
- CM.IDX: a3b3d9354c0cb718a2bccbdd2835ef3be1a3d068da6bc288303dbd338b9b180e

此外检查实际链接的 recomp target 中存在且仅存在一个对应生成调用；旧生成代码
不能靠注册函数存在而通过。该门禁共用于桌面 saturn 与 Harmony libmain。
仓库补丁不包含镜像、提取数据或生成游戏源码。

## 重建与验证

先保留个人存档，正常执行本项目资源提取流程。Windows 重新生成并构建：

```text
python tools/winbuild.py build --pal-options --recompile
```

使用现有 SDL3_DIR/--sdl-dir 配置。Harmony 首次不要复用旧 --skip-learn 生成物，
正常运行 tools/ohosbuild.py 重新生成、编译；若资产或实际生成钩子不匹配，构建会
明确失败，不要通过删除门禁或改登记哈希来绕过。

命中该特定箱子时日志包含：

```text
PAL disc fix medicine-chest-v1: scene=93 event=1661 script=36788 object=0->103 count=1
```

已经开过错误箱子的旧档不会自动补发道具。若要验证，从开箱前自己的存档正常重开。

### 补充边界审阅

私有生成函数的 10 组合成边界中，钩子路径与直接调用原 additem(103,1) 的
完整 WRAM/最终 CPU 一致，含已有堆叠和满库存。原函数会扫描索引 0..256，
而保存库存只有 256 槽：这可能向保存范围之外的第 257 扫描槽写入物品。
此原行为不属于本次药箱参数修复，尚未扩改；不能据此承诺满库时正常拒绝。
测试没有修改实际玩家的库存或存档。

OHOS 双 ABI 无签名 debug HAP 已实际编译/链接，libmain 内确认本钩子符号与
PAL_MEDICINE_ASSETS_VERIFIED=1；HAP 不含上述三个原资产。
这是编译验证，尚非 Harmony 设备开箱实测。

身份检查文件同时加入 CMAKE_CONFIGURE_DEPENDS，使通过配置后替换资产或
生成源，再直接 cmake --build 也会重新验证。缺资源的资产集成测试会明确跳过。
本轮唯一原有 skip 为可选 keyboard upstream 集成，未设置
PAL_KEYBOARD_UPSTREAM_RUNTIME；其它门禁/药箱用例实际执行。

新二进制无输入启动至 6800 VBlank 正常退出，6700 帧实见标题；影片声音缓存刷新
日志仍为 progress=25A007A0。OHOS 实际 ARM64 增量构建也验证过：修改一个私有
CM.NOR 字节或移除生成 hook 后，只执行 build 即自动重配置并拒绝；恢复原字节
后 main 构建通过。
