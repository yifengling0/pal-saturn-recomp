# 横屏、竖屏与分屏窗口布局

本次改动在宿主显示层实现，不改游戏逻辑、步进/按压时序或音频队列。

## 鸿蒙操作

点击虚拟按键旁的三横线打开设置；若菜单按钮隐藏，从左右空白边缘向内滑动也可打开。小窗口使用“下一页”翻页，菜单页数会随窗口大小变化，不固定记页码。

要快速做横屏上下分区：找到“画面分区”选“分区”，再将“分区方向”选为“上下”；找到“移动画面”调整窗口，找到“移动按键”调整触控组，编辑后均点“完成”。

具体设置：

1. **屏幕方向**仍可选横屏、竖屏、自动。系统分屏允许的实际窗口大小优先；布局根据 SDL 渲染窗口的宽高判定，不根据物理屏幕方向猜测。
2. **画面分区**选“分区”，出现**分区方向**：自动 / 上下 / 左右。自动沿用旧版随窗口方向的方式；上下和左右明确固定方向，因此横屏也能上下分区，竖屏也能左右分区。
3. **画面占比**调节游戏区与按键区的分配（30–70%）。折叠设备的自动模式仍优先使用系统提供的折痕，手动分区不依赖折痕。
4. **画面大小**以当前区域内已适配的画面为基准缩放（40–100%）。**画面左右位置 / 画面上下位置**在剩余空间内移动，不让画面越界。若某轴铺满区域，该轴没有可移动空间；可先减小画面大小。
5. **移动画面**打开单独编辑器，拖动画面，点“完成”保存；“取消”或返回放弃草稿，“重置位置”恢复居中与100%大小。此模式不拖动虚拟按键，也不向游戏发送按钮。
6. **移动按键**沿用分组拖动编辑器。在分区模式下只能放在按键区，叠加模式下可以在整个窗口内调整。画面编辑与按键编辑互不覆盖。

横屏和竖屏各自保存画面分区、位置、大小和触控参数；每个方向内继续分别保存叠加与分区的按键位置。旋转或分屏调整导致实际窗口横竖方向切换时，立即使用对应方向的配置。编辑中的方向切换会取消未保存草稿，避免把横屏草稿写进竖屏配置；同方向调整窗口大小时保留归一化草稿但取消当前拖拽，重新按下即可继续。

“恢复画面”和“重置触控”只恢复当前方向的相关设置，不清空另一个方向、键盘/手柄映射或存档。屏幕方向本身是全局系统请求，不因恢复当前画面设置而强制旋转。

## 配置兼容

旧 `[display]` / `[touch]` 不会在启动时自动迁移或改写。尚未设置的方向继承旧值；该方向首次修改时快照为 `[display landscape]`、`[display portrait]`、`[touch landscape]` 或 `[touch portrait]`。快照写入全部相关键，包括等于默认值的键，以确保重启后不意外重新继承旧自定义值。旧 `layout=below/right` 仍保持“随窗口方向分区”的含义，新增 `split_axis=auto/below/right` 控制固定分区方向。

按键位置使用区域剩余可移动空间的归一化坐标，窗口尺寸改变不重写保存值。画面缩放在比例适配后进行；位置仅作用于空余空间，避免切换分辨率、DPI 或极端比例时裁掉画面。原始电视模式的 PAL 留边和有效行计算仍先执行。

桌面 Windows/Linux 继续使用原全窗口画面和全局触控配置，不应用鸿蒙方向快照；鼠标、键盘、手柄与音频算法保持原实现。

## 验证入口与边界

- `PYTHONPATH=tools PATH="$PWD/build/venv/bin:$PATH" build/venv/bin/python -m pytest tools/tests -q`
- `tools/tests/test_flexible_layout.py` 编译真实 Settings 和几何函数，并提取实际宿主编辑/事件清理代码验证，不是另一份实现模型。
- 回归包括旧配置继承、方向隔离、逐键往返、保存失败回滚、取消、重置、多指捕获、旋转取消草稿、同方向 resize、7类窗口/后台输入清理和多尺寸/DPI布局边界。
- 正式三平台编译与实际设备验证必须另外记录；无盘测试、Linux模拟窗口不能替代鸿蒙真机分屏/旋转测试。
