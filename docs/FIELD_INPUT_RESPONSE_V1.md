# 触摸轻点、转向与松手：field-input-v1

本轮接在 `025796e2555e3a4d791ad93b9de134a55877e202` 的构建修复之后，保留已有 0014 方向死区与 0015 非行走按压行为，新增独立 0016。目标是轻点可控、松开不继续补走。这里是 PAL 专用操作体验改良，不是通用 SMPC 硬件修复。

## 本地更新和确认

先保留自己的源码修改和 BUP 存档，再更新 `fix/linux-sdl-dma-20261010`；不要强制覆盖个人提交。

Harmony 首次更新必须重新生成 runtime 和游戏代码，不加 `--skip-learn`：

    python tools/ohosbuild.py --launch

保留自己原来使用的 `--deveco`、设备与签名配置。只有本轮完整再生成功后，相同源码后续构建才可使用 `--skip-learn`。旧 detached runtime / manifest 被拒绝时，先将旧生成目录改名备份，再走正常再生流程；不要仅将 observed hash 填入白名单。

启动日志应出现：

    field-input-v1 source-held-edge-single

普通 PC98 构建和增强构建都接入新行走逻辑；Harmony 目前仍走普通 PC98 构建。Windows 按原流程运行 `python tools/winbuild.py build --recompile`，保留原有 `--options` 选择。新模式在实时 SDL 宿主默认启用。需要对照时，可在启动进程的环境设置 `PAL_FIELD_INPUT=0`，恢复原输入路径；这不是现有触控菜单中的新开关。

## HAP 链接与参数优先级

这是对实际 `libmain.so` 链接链的源码核查，尚无本轮 OHOS SDK/HAP 真机验收：Harmony CMake 将同一份生成 `recomp` 和真实 `saturn_host` 链接进 `main` 共享库，并启用 `--no-undefined`。新生成函数直接引用 host 提供的 field API，不依赖仅加入桌面 `saturn` 的额外注册文件。现有 CMake 还检查 `saturn_host` 实际拥有的 `host.cpp` 路径，并把该文件 SHA 编进 host 对象。入口日志中的 `source_bytes_sha256` 必须对应本轮普通 host；LF 源文件值为 `c69b7a176ecf926c06ad5351c2d6b7d5edcab507c9a61639e949308190c495c6`（构建平台换行处理不同应以本轮工具验证和实际构建输出一致为准）。再核前述 `field-input-v1` feature 行，避免只看旧 HAP 文件时间。

新模式启用时，它优先处理实时行走，即使仍设置 `PAL_RESPONSIVE_INPUT=1`、`PAL_RESPONSIVE_ALIGN=1` 或 `PAL_RESPONSIVE_WAKE=1`，旧的 apply/tick/align 路径也不会叠加执行。原等待和已存在的配对呈现 bookkeeping 保留；`PAL_PAIRED_FRAME_QUEUE` 保持原来的独立开关，本轮没有在 Harmony 普通构建里强行启用它。设置 `PAL_FIELD_INPUT=0` 后，旧参数重新按旧规则生效。纯脚本回放也保留旧路径。

## 行为

- 触摸、键盘、手柄分别保留当前按住状态，释放一个来源不会清掉另一个来源。
- 轻点即使在游戏下次行动前已抬起，也只保留一个尚未消费的方向意图。由原游戏行动点消费一次；撞墙也消费，不积压到以后补走。
- 转向与这一次移动尝试在同一个原行动点处理。没有增加一次 NPC、脚本、随机数或移动函数调用。
- 松手立即结束该来源的持续按住状态。已消费的轻点不会再按固定 VBlank 数补成长按。
- 多方向或极快的新按压采用最新方向意图，不排队重播一串过时步数。长按仍在游戏原有行动时机连续移动。
- 菜单、失焦、后台、场景和真实剧情等待边界清理旧意图；普通 NPC 计算恰好跨 VBlank 不会误清输入。
- 不在 SMPC 每个字节读时重新取键。已有 INTBACK 数据包在一次事务内保持一致。
- 非行走按键和非行走场景保留原路径。纯 `--input` 回放不启用新实时输入；`--resume` 到达交接点后才启用。

输入语义参考了 [SDLPAL 固定版本 f6236a0](https://github.com/sdlpal/sdlpal/tree/f6236a0d0839b1cc8918e2abc54017e223938f1d) 的方向状态、最近按键和同次转向/行动思路，独立实现。SDLPAL 是开源重实现，不能当作闭源 Windows 98 原版的内部源码；本轮没有复制其 GPL 实现代码。

## 已验证到哪里

在 Linux 编译真实游戏逻辑，并从本任务正常游玩生成的草地存档加载，以实际 SDL 队列注入触摸事件，再由原游戏碰撞/移动函数提交位置：

- 1、3、6 VBlank 的短按各产生一次位置步，坐标变化为游戏原有的 ±16/±8。
- 同次事件泵里旧手指 ID 抬起后重新按下，只执行新的方向。
- 两指同向按住，抬起一指不会清掉另一指。
- 回到十字中心及 CANCEL 在测试中没有遗留位移。
- 长按在 VB4230 抬起，新模式最后一次位置提交为 VB4227，之后没有尾步；同一诊断程序关闭新模式时，旧路径仍在 VB4230 和 VB4233 提交位置。
- 两轮均运行到 VB4400，正常退出，源 BUP 未改变。另有实时宿主虚拟手柄八次短按各一步的交叉验证。

以上触摸事件是明确记录计划/派发 VBlank 的诊断脚本，走真实 SDL 事件队列；不是鸿蒙物理屏幕或真人手指测试。诊断注入器不进入产品。碰撞消费、触摸与键盘混合、菜单/失焦、同 ID 重用等另有独立策略和实际 SDL 宿主测试。普通与增强生成器严格校验函数身份；完整补丁链和重复准备检查通过。

仍需你本地确认手机/平板真实操作感和系统触控事件。人物逻辑位置提交与实际看见下一画面是不同时间点：本轮没有改早显、VDP1 交换或强开呈现队列。原画面排队延迟仍可能存在，不能把逻辑一步验证解释成首画面延迟已经完全消除。

## 建议本地快速检查

1. 在无 NPC、无出口、离墙稍远的地方，轻点十字四个方向，观察是否立即转向并只走一步。
2. 连续按住一方向，再抬起；确认停止后不继续补走。再做快速左右反向。
3. 手指滑回十字中心、滑离按键、开关设置菜单、切后台再返回，确认没有残留方向。
4. 若接键盘或手柄，保持同向按住的同时抬起触摸，确认另一个来源仍可控制。
5. 若仍异常，提供启动 feature 行、使用的输入设备、具体手势和短录屏。不要删除自己的存档或先改全局帧率。

## 输入录制的边界

旧 `--record-input` 记录的是每 VBlank 采样到的外设按住状态，不包含新模式已消费的轻点意图。短按可以在抬起后执行一次，而旧 pad 日志中没有对应按住帧；因此不能保证把该日志再交给纯 `--input` 后逐动作复现新实时操作。本轮的可重复触摸验证保存了实际 SDL 事件脚本，以及计划/实际派发 VBlank。

本批没有新增产品事件录制功能。需要可追溯调试时保留录屏、具体手势及启动参数；工程中的新模式回归应保存 SDL 事件输入。若继续使用原有纯 pad 脚本验证流程，应明确 `PAL_FIELD_INPUT=0` 或纯脚本路径，不能把它当作新触摸模式的验收。
