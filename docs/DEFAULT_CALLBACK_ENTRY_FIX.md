# 修复：正常战败返回标题时退出程序

## 现象与原因

台湾版 T-37401H / V1.000 / JT 的赤鬼王长战复放中，队伍战败并显示“胜败乃兵家常事也，大侠请重新来过吧”后，程序报：

```
call to 0605D66C, not an entry of an active module (from pr 060600E8)
```

这是合法代码入口漏注册。原盘 PROG 的 `0605D66C` 是独立的 `rts; nop` 空回调。函数 `0605D660` 在传入空回调时通过 MOVA 取得它，并在 RTS 延迟槽写入 `GBR+20`。固定上游版本的入口发现扫描在 RTS 处结束，没有继续分析这个延迟槽写入。之后游戏正常调用槽中默认回调时，严格分派器找不到其注册入口。

确定性原版复放在 VB113539 读到回调槽 `060FFC14` 从 `06026094` 改成 `0605D66C`，live 目标字节与原盘一致；下一步触发原故障。PROG 模块身份、调用位置、返回地址均一致。此前 VB113013 已正常显示战败文本；这不是战斗胜利后的退出。

## 最小修复

在 `tools/seeds.json` 的 PROG 明确入口中加入 `0605D66C`。保留原有 seed，不改运行时分派规则，不吞掉未知入口错误，也不将整段数据注册成函数。

重新生成仅新增一个函数（PROG 1010 → 1011），156 个后续覆盖率 `ran[]` 索引随之移动。既有函数指令和语义不变。本次同型窄扫描的另一处 MOVA → 空回调 `06060394` 原已注册，没有发现另一个同型遗漏。

## 更新与重建

本批只影响生成入口，不增加运行时补丁，也不要求重置配置或存档。保留本地修改后更新同一 feature 分支，再**重新生成并编译**；仅复制 seeds.json 或重打包旧可执行文件无效。

Windows（已有可用构建环境）：

```powershell
$PY = '.\build\venv\Scripts\python.exe'
& $PY tools/winbuild.py build --recompile
# 若原先使用增强独立构建，请保留原来的 --pal-options、--build-dir 等选项重新编译。
```

Harmony：先执行上面重新生成命令，再使用：

```powershell

```

这里的 `--skip-learn` 只用于**前一步已用新 seed 再生成功**的产物，不能跳过首次再生。OHOS 的 SDK、签名及 UI13 身份条件与此前版本相同。

Linux 使用原有 `tools/linuxbuild.py` 构建流程重新生成编译。生成后的 `p_prog_table.cpp` 应有 `0605D66C`，`p_prog_funcs.h` 应声明它；不要手改生成表冒充完整重编。
