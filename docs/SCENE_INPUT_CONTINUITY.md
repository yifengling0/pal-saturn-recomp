# 切换地图时持续方向输入

本项修复针对台湾版 T-37401H/V1.000/JT。原游戏在装载资源和切换地图时会设置等待松键标志；如果方向始终按住，角色可能一直停在新场景入口，直到松开再按。

## 实现边界

- 保留原游戏的等待松键字节，不全局清除，也不制造一次假的松键。
- 只在原游戏正常行走决策点，对已确认的资源加载或纯切场来源，允许仍然持续按住的方向参与原来的移动计算。
- 淡出在实际切场标志之前发生。准确淡出调用入口先冻结原来的持续按键来源；只有脚本最终真的切场，且没有其它交互等待或硬边界，才允许延续。
- 加载期间新按、松开再按、触摸接触身份变化、换方向、失焦、菜单等情况不能把旧方向资格转给新输入。
- 对话、确认、取消、战斗及未知脚本来源继续使用原有保护。
- 加载期间原游戏倒计时可能累积为负值。恢复时不把积累循环兑换成多步移动：在原游戏已选定行走间隔之后，仅拒绝这次切场延续方向的过早位移尝试，保留动作、朝向、间隔、计时器和原移动函数调用。欠下的移动不会排队补发。
- CPU/VBlank、动画、音频时钟没有调速；没有新增 NPC、脚本或 RNG 调用。玩家走到的位置不同会影响后续游戏轨迹，零位移分支也可能少走碰撞查询，因此不承诺与原版位级 RNG/周期相同。

## 构建与对照

需要正常重新生成游戏代码再编译。不要使用旧生成目录或旧二进制的 `--skip-learn` 结果来判断修复是否包含。

PC 可沿项目原命令构建：

```sh
python tools/winbuild.py build --pal-options --recompile
```

OHOS 使用项目正常重建流程，让脚本重新准备当前补丁与生成代码。补丁列表严格要求每个编号唯一；不得用旧脚本静默跳过新增补丁。

进入游戏地图后，日志显示：

```text
PAL field continuity v1: enabled=1
```

本功能在默认 FIELD1 实时输入桥接可用时开启。设置环境变量 `PAL_FIELD_CONTINUITY=0` 可关闭本次切场延续；`PAL_FIELD_INPUT=0` 关闭实时桥接时，本次延续也停用，保持传统采样的原行为。headless、尚未结束的脚本输入或宿主实时输入不可用时同样停用，不根据环境变量假定实际能力。启动日志的 enabled 是进入地图函数当时的可用状态；脚本读档结束后实时桥接可动态生效。

FIELD0 的传统手柄采样只能观察采样时刻的电平。候选测试发现，在加载中松手，缓存方向可滞后到恢复后造成两步额外移动，因此最终实现不给 FIELD0 新豁免，也没有提供不安全的旧采样实验开关。FIELD1 保留来源和接触身份，可及时撤销这类资格。旧 `--record-input` 不是 FIELD1 的完整事件重放；真实 SDL 测试应另记输入事件及实际派发时刻。

## 本地复测

1. 提前按住方向穿过普通地图出口，保持按住，检查进入新地图后能自然继续走。
2. 在黑屏/淡出时松手，确认新地图没有额外自动走；再轻点与快速换向。
3. 对话或菜单期间持续方向，关闭后检查确认/取消没有被穿透，也没有旧方向积压。
