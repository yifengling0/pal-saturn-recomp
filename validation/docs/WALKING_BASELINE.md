# 走路基线采集协议：逻辑、动画、世界与镜头分开

本协议目前未在《仙剑》实盘运行。示例 CSV 和本轮指标均为合成数据，不代表游戏真实速度或异常。

## 采集前必须确认

- 完整镜像、实际语言/版本/补丁、哈希、构建提交、配置与编译器版本。
- 参考运行器/实机条件、合法 BIOS 如需要、存档或开局路径、RTC/随机条件、输入设备。
- 场景、角色、地图和碰撞条件一致；建议固定开阔直线、转角/撞墙、斜向、地图滚动边界、切图后的重新移动各一段。
- 查明“游戏逻辑 tick”对应的实际计数器/更新函数及证据。上游 VBlank 是硬件时序，宿主呈现 FPS 是展示频率，不能默认任一个等于逻辑更新次数。
- 查明世界坐标、相机坐标、动画状态的真实语义、单位和存储位置。没有证据则字段留空，不能把玩家屏幕位置猜成世界坐标。

## 每次运行保存

1. `capture_metadata.json`：镜像和模块哈希、运行器/构建版本、坐标与 tick 的证据路径、场景、输入脚本、参考帧、是否补丁版。
2. 原始按键按 VBlank 记录，另保存每次采样的逻辑 tick 对照。仅在同一逻辑 tick/场景内对齐参考与重编译结果。
3. `capture.csv`：以下字段；每个逻辑 tick 一条采样。计数器回绕、载入重置、场景突变先分段，不静默排序或插值。
4. 原始截图/视频/运行日志，记录在哪一逻辑 tick 截取；监测运行时写入时保留写入地址、来源函数、值和时刻的原始记录。

CSV 必要列：

- `game_tick`：已证明的游戏逻辑计数，严格递增
- `vblank`：运行器/参考观测的 VBlank，非递减
- `world_x,world_y`：世界位置；未知时空白
- `camera_x,camera_y`：镜头位置；未知时空白
- `animation_frame`：真实动画帧/状态标识；未知时空白
- `input`：本段输入标签，如 `RIGHT`、`IDLE`；不要把示例当上游按键语法
- `map_id`：已验证场景标识，避免跨切图算距离
- `render_present_count`：宿主呈现累计次数，单独记录

额外可以记录单调墙钟时间、逻辑函数入口计数、碰撞状态、角色面向、速度变量、调度暂停原因、音频和帧编号；无需先编造地址。

## 最小实验矩阵

- 参考实现原版：相同开局/存档及输入至少重复两次，建立可重复性。
- Linux 重编译未修改版：相同逻辑 tick 范围和路线至少重复两次。
- 仅改变宿主呈现条件（如窗口刷新/解锁呈现）：验证每逻辑 tick 位移及动画推进是否稳定。
- 仅改变计划中的代码修复：对照上述基线；保留完全未修改版本以回滚。
- 插值开关作为独立变量，不与移动逻辑修复混成一次实验。

## 计算与解释

运行：

```bash
python -m pal_validate walking --csv capture.csv \
  --input-kind reference_capture --out build/reference-walk-001.json
python -m pal_validate walking --csv capture-recompiled.csv \
  --input-kind recompiled_capture --out build/recompiled-walk-001.json
```

工具只对相邻逻辑 tick、同一地图和同一输入标签计算差分；跳 tick、切图或输入改变的样本对被排除并计数。输出包含世界和镜头每 tick 位移、观测路径总长、零位移比例、动画转换比例。坐标缺失时明确 unavailable。

对比时还应分开审阅：固定移动输入下的步速分布、动画驻留 tick 序列与循环长度、相机滚动增量、角色屏幕位置减相机位移后的视觉节奏。当前小工具不自动判断动画循环，也不自动把分段汇总等同于整条路径完成。

零位移可以来自 idle、碰撞、低频角色更新或停顿，不能单凭比例判“卡顿”；动画变化次数也不能独立证明正确动画速度。要定位根因，必须将异常 tick 与实际游戏函数、位置写入、动画推进和调度路径相连。宿主平均 FPS 只作为性能附带信息。

## 强制结论边界

- 缺真实游戏输入：只说明测量工具就绪。
- 无世界坐标语义证据：不能报告实际游戏移动速度。
- 无参考基线：不能报告“已修复原版走路问题”。
- 无受控前后对比：不能把画面更流畅解释成逻辑正确。
- 缓存或自修改代码可作为风险调查方向，但本轮没有证据把它归为走路根因。
